# Erp

نرم‌افزار ERP — ماژول اول: هسته مالی (حسابداری)

## پیش‌نیازها
- .NET 10 SDK
- SQL Server 2022 یا 2025 (Developer یا Express) + SSMS
- VS Code با افزونه C# Dev Kit (یا Visual Studio)

## اجرا
- در VS Code: پوشه را باز کنید و **F5** بزنید (پروژه Erp.Api).
- یا در ترمینال: `dotnet run --project src/Host/Erp.Api`
- یا برای تست کامل: `tools\run-test.bat` (نتیجه در `tools\test-log.txt`)

بار اول دیتابیس `ErpCompany_Default` روی `.\ERP` ساخته می‌شود و کدینگ استاندارد (۲۸۴ حساب)،
۱۴ نوع تفصیلی، ارزها، واحدها و تقویم شمسی ۱۳۹۵ تا ۱۴۲۰ بارگذاری می‌شوند.

- رابط کاربری: `http://localhost:5227/` — منو: «مالی ← حسابداری» (اسناد، گزارش‌ها، تعاریف) و «اطلاعات پایه» (اشخاص، نقش‌ها، جدول‌های پایه، بانک‌ها)
- صفحه تست API: `http://localhost:5227/scalar`
رشته اتصال در `src/Host/Erp.Api/appsettings.json` بخش `Companies` است.

## ساختار
```
database/                              اسکریپت‌های SQL — مرجع ساختار دیتابیس (README داخلش را بخوانید)
src/
  BuildingBlocks/
    Erp.SharedKernel                   پایه مشترک: Entity، رویداد دامنه، تاریخ شمسی، یکسان‌سازی متن فارسی
    Erp.Database                       اجراکننده اسکریپت‌های database/migrations + CompanyConnection (اتصال و تراکنش مشترک ماژول‌ها)
  Modules/BaseData/                    اطلاعات پایه (schema base): اشخاص، نقش‌ها، جدول‌های پایه، بانک‌ها
    Erp.BaseData.Contracts             قرارداد بین ماژول‌ها (PersonKind، RoleCodes، IPersonLinks)
    Erp.BaseData.Domain / Application / Infrastructure
  Modules/Costing/                     بهای تمام‌شده (schema cost): انواع هزینه، عوامل هزینه، انواع و مراکز هزینه
    Erp.Costing.Contracts              قرارداد (CostNature، CostFunction، CostBehavior، ICostDetailLinks)
    Erp.Costing.Domain / Application / Infrastructure
  Modules/Accounting/
    Erp.Accounting.Domain              قواعد حسابداری (کدینگ، تفصیلی شناور، سال/دوره مالی، سند)
    Erp.Accounting.Application         سرویس‌ها و DTOها
    Erp.Accounting.Infrastructure      نگاشت EF Core به جدول‌های fin (و نمای فقط‌خواندنی نقش اشخاص)
  Host/Erp.Api                         میزبان: Web API + رابط کاربری Blazor (Components/)
tests/Erp.Accounting.Tests             تست قواعد دامنه
tools/                                 run-test.bat و تنظیمات اختیاری VS Code
```

**Modular Monolith**: هر ماژول (اشخاص، خزانه، انبار، خرید، فروش، حقوق، بهای تمام شده) یک پوشه زیر
`Modules` با همین سه لایه دارد. زیرسیستم‌ها سند را مستقیم نمی‌نویسند؛ از موتور سند و الگوهای
`fin.PostingTemplates` استفاده می‌کنند و مرجع سند منبع در `SourceModule/SourceDocType/SourceDocumentId` می‌ماند.

## تصمیم‌های هسته مالی (سند «طراحی هسته مالی»)
- کدینگ سه‌سطحی گروه/کل/معین، پایه رایا بیلان (نشریه ۱۶۶ و استاندارد ۱). حساب استاندارد قفل است؛
  شرکت حساب اختصاصی با کد شروع‌شونده از کد والد اضافه می‌کند
- ۶ سطح تفصیلی **شناور**: هر معین برای هر سطح، الزامی بودن و انواع تفصیلی مجاز را تعیین می‌کند؛
  نوعی که گردش دارد از قاعده حذف نمی‌شود
- هر شخص یک تفصیلی مشترک برای همه نقش‌های طرف‌حسابی (اشخاص حقیقی 01001 تا 03999، حقوقی 04001 تا 06999)
  و در صورت نقش کارمند یک تفصیلی کارکنان؛ همه با PersonId به شخص وصل‌اند
- سال مالی با ۱۲ دوره؛ دوره قابل قفل
- سند: پیش‌نویس ← موقت ← دائم (و باطل). شماره موقت از ابتدا، شماره قطعی هنگام دائم شدن، پیوسته
- ارز، نرخ، مقدار، واحد و شماره/تاریخ پیگیری در ردیف سند
- یک دیتابیس برای هر شرکت؛ شرکت با هدر `X-Company` انتخاب می‌شود
- تاریخ میلادی ذخیره می‌شود؛ API تاریخ شمسی (`1405/07/21`) می‌گیرد و برمی‌گرداند
- ي/ك عربی و ارقام فارسی در همه ورودی‌ها و جستجوها یکسان‌سازی می‌شوند

## رابط کاربری
Blazor (Interactive Server) با MudBlazor، راست‌به‌چپ و فونت وزیرمتن (محلی، بدون CDN).
صفحه‌ها سرویس‌های لایه Application را مستقیم صدا می‌زنند؛ هر عملیات در scope جدا اجرا می‌شود
(`Components/Shared/Backend.cs`) تا DbContext در اتصال طولانی کاربر نماند.

## اشخاص و تفصیلی مشترک
- هر شخص **یک تفصیلی مشترک** برای همه نقش‌های طرف‌حسابی دارد (مشتری، تأمین‌کننده، پیمانکار، سهامدار، شرکت وابسته، ...)
  تا مانده کامل او یک‌جا دیده شود. گروه آن «اشخاص حقیقی» یا «اشخاص حقوقی» است.
- نقش‌ها فقط برچسب‌اند؛ کاربر نقش جدید هم می‌تواند تعریف کند (`/base/roles`). نقش **کارمند** تفصیلی جدا در گروه کارکنان دارد.
- در قواعد تفصیلی هر معین «نقش‌های مجاز» تعیین می‌شود؛ فهرست اشخاص در فرم سند به آن‌ها **فیلتر نرم** می‌شود
  (آیکون قیف: نمایش همه اشخاص). ثبت شخص بدون آن نقش ممنوع نیست.
- اطلاعات شخص: هویتی/ثبتی، گروه شخص (درختی)، مالیات و سامانه مودیان، تماس و چند نشانی (نوع، استان، شهر)، افراد رابط،
  حساب‌های بانکی (بانک از جدول بانک‌ها با کد شبا یا پیش‌شماره کارت تشخیص داده می‌شود)، مدارک پیوست (تا ۱۰ مگابایت).
- پیش از ذخیره، اشخاص مشابه (کد ملی، موبایل، شبا یا نام یکسان) هشدار داده می‌شوند.
- اطلاعات کارگزینی (استخدام و ترک کار، حکم، کارگاه، شغل، تحصیلات) در این فرم نیست؛ ماژول کارگزینی فرم‌های خودش را خواهد داشت.
- **جدول‌های پایه** (`/base/lookups`): کشور، استان، شهر (زیر استان)، نوع نشانی، گروه اشخاص، سمت رابط؛ و **بانک‌ها** (`/base/banks`).
  اقلام سیستمی حذف نمی‌شوند؛ قلم استفاده‌شده هم حذف نمی‌شود و فقط غیرفعال می‌شود.
- **حذف امن**: هر حذفی با پرسش تأیید است و فقط وقتی انجام می‌شود که جایی استفاده نشده باشد
  (شخص بدون گردش تفصیلی، تفصیلی بدون ردیف سند، حساب اختصاصی بدون زیرحساب و گردش، سند فقط پیش‌نویس، سال بدون سند).
- کنترل صحت (سرور و فرم، `Erp.SharedKernel.Validation.IranianIds`): کد ملی و شناسه ملی و کارت با رقم کنترل، شبا با mod-97
  (و تشخیص بانک)، موبایل، تلفن، کد پستی، کد اقتصادی، کد فراگیر اتباع، شماره بیمه؛ ارقام فارسی خودکار تبدیل می‌شوند.
- **گروه‌های تفصیلی** (`/detail-types`): تعریف گروه با طول کد و بازه، پیش‌نمایش ظرفیت و کد بعدی، بازه‌های آزاد و الگوی پیشنهادی.
  بازه با حفظ کدهای موجود بزرگ/کوچک می‌شود؛ طول کد و مالک گروهی که تفصیلی دارد ثابت است.
  صفحه هر گروه (`/detail-types/{id}`) تفصیلی‌هایش را نشان می‌دهد؛ تفصیلی‌های غیرشخصی (مرکز هزینه، پروژه، ...) همان‌جا افزوده، تغییر نام، غیرفعال و حذف می‌شوند.

## ساختار هزینه‌ها و بهای تمام‌شده
- گروه ۷: **کل = ماهیت**، **معین = وظیفه**
  - 70 مواد مصرفی: 7001 تولیدی، 7002 پیمانکاران (بدون تفصیلی؛ بعداً از محاسبه بهای تمام‌شده می‌آید)
  - 71 حقوق و دستمزد، 72 استهلاک، 73 سایر هزینه‌های عملیاتی: هر کدام معین تولیدی، خدماتی (پشتیبانی تولید)، اداری، فروش و توزیع
  - 76 هزینه‌های مالی (تأمین مالی): یک معین، بدون تفکیک وظیفه
- تفصیلی معین‌های هزینه: **سطح ۱ عامل هزینه**، **سطح ۲ مرکز هزینه** (هزینه مالی: سطح ۲ قرارداد تسهیلات، اختیاری).
  عامل فقط در کلِ گروه خودش و مرکز فقط در معینِ وظیفه نوعش ثبت می‌شود (کنترل در فرم سند، سرور و تریگر دیتابیس).
- **انواع هزینه** (`/costing/expense-types`): قابل تعریف، هر کدام زیر یکی از چهار گروه.
- **عوامل هزینه** (`/costing/factors`): نوع هزینه + رفتار (ثابت، متغیر، نیمه‌متغیر با درصد جزء متغیر)؛ ۵۹ عامل پیش‌فرض از معین‌های قبلی.
- **انواع مرکز هزینه** (`/costing/center-types`) با وظیفه؛ چهار نوع سیستمی و نوع‌های ریزتر تعریف کاربر.
- **مراکز هزینه** (`/costing/centers`): نوع، بالادست، مسئول؛ برای بهای تمام‌شده: مراکز خدماتی/اداری مبنا و ترتیب تسهیم و
  مراکز گیرنده با سهم (جمع ۱۰۰)، مراکز تولیدی مبنای جذب سربار، فروش بدون تسهیم. مبناها در جدول پایه «مبنای تسهیم و جذب».
- تفصیلی عامل‌ها و مراکز خودکار ساخته می‌شود (مثل اشخاص)؛ عامل/مرکزِ در سند آمده گروه یا وظیفه‌اش عوض و حذف نمی‌شود.

## قاعده تفصیلی پیش‌فرض معین‌ها
اسکریپت ۰۷ برای همه معین‌هایی که قاعده نداشتند قاعده می‌گذارد؛ مثلاً بانک و صندوق الزامی، دریافتنی‌ها با اشخاص و نقش مشتری،
پرداختنی‌ها با تأمین‌کننده، معین‌های «شرکت‌ها» فقط اشخاص حقوقی و «اشخاص حقیقی» فقط حقیقی، اسناد نزد بانک با شخص و بانک،
وام و مساعده با کارکنان، تسهیلات با قرارداد تسهیلات. همه از صفحه کدینگ قابل تغییرند.

## گزارش‌ها
- **تراز آزمایشی** (`/reports/trial-balance`): سطح گروه، کل، معین و تفصیلی؛ نمایش ۴ یا ۶ ستونی؛
  فیلتر بازه تاریخ، بازه شماره قطعی سند، موقت/دائم و حذف اسناد بستن و اختتامیه.
  با کلیک روی گروه ← کل‌ها، روی کل ← معین‌ها، روی معین ← دفتر. دکمه کنار معین ← تراز تفصیلی همان معین.
  در تراز ۶ ستونی، سند افتتاحیه همیشه جزو «مانده ابتدای دوره» است.
- **دفتر معین و تفصیلی** (`/reports/ledger`): مانده ابتدای بازه، ردیف‌ها با مانده جاری و تشخیص بد/بس؛ کلیک روی ردیف ← سند.
- API: `POST /api/accounting/reports/trial-balance` و `POST /api/accounting/reports/ledger`.
- پیش‌نویس و باطل هیچ‌وقت در گزارش نمی‌آیند.

## تست‌ها
`dotnet test` تست‌های دامنه را اجرا می‌کند. تست‌های گزارش روی SQL Server واقعی‌اند و فقط وقتی اجرا می‌شوند که
متغیر `ERP_TEST_SQL` تنظیم شده باشد؛ `tools\run-test.bat` آن را روی دیتابیس جداگانه `ErpCompany_Test` تنظیم می‌کند
(هر بار از صفر ساخته می‌شود و به دیتابیس اصلی کاری ندارد).
