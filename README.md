# Erp

نرم‌افزار ERP — ماژول اول: هسته مالی (حسابداری)

## پیش‌نیازها
- .NET 10 SDK
- SQL Server 2022 یا 2025 (Developer یا Express) + SSMS
- VS Code با افزونه C# Dev Kit (یا Visual Studio)

## اجرا
- در VS Code: پوشه را باز کنید و **F5** بزنید (پروژه Erp.Api).
- یا در ترمینال: `dotnet run --project src/Host/Erp.Api`
- یا برای تست کامل: `tools\run-test.bat` (نتیجه در `tools\test-log.txt`)

بار اول دیتابیس `ErpCompany_Default` روی `.\ERP` ساخته می‌شود و کدینگ استاندارد (۲۸۴ حساب)،
۱۴ نوع تفصیلی، ارزها، واحدها و تقویم شمسی ۱۳۹۵ تا ۱۴۲۰ بارگذاری می‌شوند.

- رابط کاربری: `http://localhost:5227/` (اسناد، ثبت سند، کدینگ، اشخاص، سال مالی)
- صفحه تست API: `http://localhost:5227/scalar`
رشته اتصال در `src/Host/Erp.Api/appsettings.json` بخش `Companies` است.

## ساختار
```
database/                              اسکریپت‌های SQL — مرجع ساختار دیتابیس (README داخلش را بخوانید)
src/
  BuildingBlocks/
    Erp.SharedKernel                   پایه مشترک: Entity، رویداد دامنه، تاریخ شمسی، یکسان‌سازی متن فارسی
    Erp.Database                       اجراکننده اسکریپت‌های database/migrations
  Modules/Accounting/
    Erp.Accounting.Domain              قواعد حسابداری (کدینگ، تفصیلی شناور، سال/دوره مالی، سند)
    Erp.Accounting.Application         سرویس‌ها و DTOها
    Erp.Accounting.Infrastructure      نگاشت EF Core به جدول‌های fin و base
  Host/Erp.Api                         میزبان: Web API + رابط کاربری Blazor (Components/)
tests/Erp.Accounting.Tests             تست قواعد دامنه
tools/                                 run-test.bat و تنظیمات اختیاری VS Code
```

**Modular Monolith**: هر ماژول (اشخاص، خزانه، انبار، خرید، فروش، حقوق، بهای تمام شده) یک پوشه زیر
`Modules` با همین سه لایه دارد. زیرسیستم‌ها سند را مستقیم نمی‌نویسند؛ از موتور سند و الگوهای
`fin.PostingTemplates` استفاده می‌کنند و مرجع سند منبع در `SourceModule/SourceDocType/SourceDocumentId` می‌ماند.

## تصمیم‌های هسته مالی (سند «طراحی هسته مالی»)
- کدینگ سه‌سطحی گروه/کل/معین، پایه رایا بیلان (نشریه ۱۶۶ و استاندارد ۱). حساب استاندارد قفل است؛
  شرکت حساب اختصاصی با کد شروع‌شونده از کد والد اضافه می‌کند
- ۶ سطح تفصیلی **شناور**: هر معین برای هر سطح، الزامی بودن و انواع تفصیلی مجاز را تعیین می‌کند؛
  نوعی که گردش دارد از قاعده حذف نمی‌شود
- بازه کد تفصیلی به تفکیک نقش (مثلاً مشتری حقیقی 01001 تا 02999)؛ هر شخص برای هر نقش یک تفصیلی
  می‌گیرد و همه با PersonId به هم وصل‌اند
- سال مالی با ۱۲ دوره؛ دوره قابل قفل
- سند: پیش‌نویس ← موقت ← دائم (و باطل). شماره موقت از ابتدا، شماره قطعی هنگام دائم شدن، پیوسته
- ارز، نرخ، مقدار، واحد و شماره/تاریخ پیگیری در ردیف سند
- یک دیتابیس برای هر شرکت؛ شرکت با هدر `X-Company` انتخاب می‌شود
- تاریخ میلادی ذخیره می‌شود؛ API تاریخ شمسی (`1405/07/21`) می‌گیرد و برمی‌گرداند
- ي/ك عربی و ارقام فارسی در همه ورودی‌ها و جستجوها یکسان‌سازی می‌شوند

## رابط کاربری
Blazor (Interactive Server) با MudBlazor، راست‌به‌چپ و فونت وزیرمتن (محلی، بدون CDN).
صفحه‌ها سرویس‌های لایه Application را مستقیم صدا می‌زنند؛ هر عملیات در scope جدا اجرا می‌شود
(`Components/Shared/Backend.cs`) تا DbContext در اتصال طولانی کاربر نماند.

## هنوز باقی‌مانده
- موتور سند و الگوهای سند زیرسیستم‌ها (جدول‌ها آماده‌اند)
- ثبت ردپای تغییرات در `audit.ChangeLog`
- دیتابیس مرکزی (شرکت‌ها، کاربران، لایسنس) و احراز هویت؛ فعلاً کاربر ثابت با شناسه ۱
- موارد «نیاز به تصمیم» برگه اصلاحات فایل کدینگ
