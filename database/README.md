# دیتابیس

ساختار دیتابیس هر شرکت **فقط** با اسکریپت‌های این پوشه ساخته و تغییر می‌کند (نه با EF Migrations).
برنامه هنگام اجرا (فعلاً فقط در محیط Development) دیتابیس شرکت را اگر نبود با Collation
`Persian_100_CI_AI` می‌سازد و اسکریپت‌های اجرانشده را به ترتیب نام اجرا می‌کند.
اسکریپت‌های اجراشده در جدول `dbo.SchemaVersions` ثبت می‌شوند.

| پوشه | محتوا |
|---|---|
| `migrations/` | اسکریپت‌هایی که روی هر دیتابیس شرکت اجرا می‌شوند (ساختار + داده پایه) |
| `tests/04_smoke_test.sql` | تست قواعد دیتابیس؛ همه ردیف‌ها باید «قبول» باشند. داده‌هایش را خودش پاک می‌کند |
| `manual/00_create_database.sql` | ساخت دستی دیتابیس دمو در SSMS (برنامه خودش این کار را می‌کند) |
| `source/coding-template.xlsx` | منبع کدینگ: پایه رایا بیلان، پاک‌سازی‌شده؛ برگه «اصلاحات و تصمیم‌ها» موارد باز را دارد |

## قواعد

1. **اسکریپتی را که یک بار اجرا شده هیچ‌وقت ویرایش نکنید.** تغییر جدید = اسکریپت جدید با شماره بعدی،
   مثلاً `05_add_cost_centers.sql`. (اگر اسکریپت اجراشده تغییر کند، برنامه هشدار می‌دهد.)
2. هر اسکریپت در یک تراکنش اجرا می‌شود؛ اگر خطا بدهد هیچ بخشی از آن ثبت نمی‌شود.
3. `GO` جداکننده دسته‌هاست، مثل SSMS.
4. اگر با `sqlcmd` اجرا می‌کنید، حتماً `-I` بدهید (QUOTED_IDENTIFIER برای ایندکس‌های فیلترشده لازم است):
   `sqlcmd -S .\ERP -E -I -f 65001 -d ErpCompany_Default -i tests\04_smoke_test.sql`

## قواعد کسب‌وکار در دیتابیس

تریگرها و constraint ها پشتیبان آخرند (قواعد اصلی در C# اجرا می‌شوند)؛ پیام خطایشان فارسی است
و API همان پیام را نشان می‌دهد. شماره خطاها:

| شماره | قاعده |
|---|---|
| 50001 | والد حساب باید دقیقاً یک سطح بالاتر باشد |
| 50002 | کد تفصیلی خارج از بازه نوعش |
| 50003 | هم‌پوشانی بازه کد انواع تفصیلی |
| 50010 / 50011 | سند دائم و ردیف‌هایش قابل تغییر نیستند |
| 50012 | ثبت فقط در معین |
| 50013 | سند موقت/دائم: حداقل دو ردیف و تراز |
| 50014 / 50015 / 50016 | تاریخ خارج از سال / سال بسته / دوره قفل |
| 50020 تا 50022 | ساخت سال مالی (ماه شروع، تقویم، هم‌پوشانی) |
